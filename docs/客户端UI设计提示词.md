## 提示词正文

### 0. 你的角色

你是一位专注 Windows 桌面效率工具的高级产品设计师，同时负责设计系统。你做过输入法、剪贴板工具、录屏工具或音频工具，理解「常驻后台、热键唤起、不能打断用户」这类产品的设计约束。你要交付的是可以直接落地到 Qt/PySide6 的高保真设计，而不是一张好看的概念图。

### 1. 产品背景（必须先理解）

- 产品名：**mao-voice**，中文语境下的 AI 语音输入工具，仅支持 Windows。
- 一句话：按一下热键开始录音，再按一下结束；本地 Whisper 识别，可选大模型保守纠错，干净文本直接注入当前输入框。
- 核心用户：中文知识工作者、开发者、写作者、需要长时间打字的人；在意隐私，愿意为「不打断心流」付出一点配置成本。
- 产品性格：安静、精确、可信、克制。它应该像一件称手的仪表，而不是一个会发光的 AI 产品。
- 当前技术栈：Python + PySide6（Qt Widgets/QSS/QPainter），悬浮胶囊、托盘、主窗口都在同一个进程；后续会用 QSS 和自绘实现，不能依赖 Web 专属效果。
- 当前版本是「客户端预览」：功能骨架已经可用，视觉和交互需要整体重做。

### 2. 设计范围

主窗口：默认 **1000 × 660**，允许缩放，最小 **860 × 560**；无边框 + 自定义标题栏；深色为默认主题，同时提供浅色主题。

需要设计的界面：

1. 首次启动向导（5 步）
2. 首页（仪表盘）
3. 历史
4. 词库
5. 设置
6. 悬浮胶囊（录音 / 转写 / 注入 / 提示 / 错误）
7. 托盘菜单
8. 通用状态：空状态、加载状态、错误状态、hover / focus / disabled

不需要设计：移动端、网页版、输入法键盘、团队协作、付费/订阅页。

### 3. 现状问题（设计要解决的）

当前界面虽然功能齐全，但看起来像「把设置页放大了」：

- 所有页面都是同一种深色圆角卡片 + 表单，层次扁平，没有视觉重点。
- 首页、历史、词库、设置长得太像，用户切页时缺少方位感。
- 字号、间距、边框、按钮样式不统一，像工程原型。
- 空状态只有一行灰字，没有引导。
- 录音状态、模型状态、错误状态缺少明确的主次关系。
- 过度依赖边框和卡片分隔，留白不足。
- 没有品牌记忆点，放在一堆 Windows 工具里认不出来。

### 4. 设计方向（必须遵守）

**关键词**：quiet instrument（安静的仪表）、editorial（编辑感）、precise（精确）、warm dark（有温度的深色）、trustworthy（可信）。

**视觉原则**：

1. **一屏只回答一个问题**。首页回答「现在能不能用、刚才说了什么、今天用了多少」，不要把设置项堆上来。
2. **用排版建立层级，不用边框堆叠**。优先用字号、字重、留白和一条细分隔线，而不是每块内容都套卡片。
3. **深色是主角，浅色是同构版本**。深色不要纯黑，用带一点蓝灰的炭色；浅色不要纯白，用微暖的纸白。
4. **单一强调色**。蓝色只用于「当前可执行的主操作」和「录音中」；成功/警告/错误各有固定色，不混用。
5. **原生桌面感**。参考 Windows 11 Fluent 的克制和信息密度，但不要照搬 Mica、亚克力、系统控件皮肤。
6. **动效只服务于状态**。录音波形、状态切换、面板展开，150–220ms，ease-out；不做弹跳、发光、粒子。
7. **中文优先**。所有文案按中文阅读节奏设计，不要把英文界面直接翻译过来。

**不要出现**：紫蓝渐变、霓虹描边、玻璃拟态、AI 光效、3D 插画、超大圆角卡片墙、彩色阴影、无意义装饰线、英文装饰字。

### 5. 信息架构

```text
首次启动向导（仅一次）
  1 欢迎与隐私边界
  2 麦克风检测与试录
  3 选择并下载模型
  4 热键与交互方式
  5 纠错与隐私（API Key 可跳过）

主窗口
  首页
  历史
  词库
  设置（通用 / 识别 / 纠错 / 注入 / 隐私 / 关于）
  可选：模式（按应用切换配置，设计预留，不要求首版实现）
```

导航建议：左侧 180–200px 纵向导航，底部放版本号与「退出」；不要用顶部横向 Tab。

### 6. 逐页要求

#### 6.1 首次启动向导

- 5 步，顶部有细进度指示，不要用大圆点。
- 第 2 步必须先让用户「说一句」并看到波形与测试结果，再进入下一步。
- 第 3 步模型选择：Small / Medium 两张选项，显示体积、速度/准确度差异、下载进度、可暂停。
- 第 4 步热键：现场按一次验证，显示冲突提示。
- 第 5 步 API Key 可跳过，明确写「不填也能用，输出原始转写」。
- 任何一步都不能强制登录或付费。

#### 6.2 首页

必须包含：

- 当前状态：就绪 / 录音中 / 转写中 / 模型未就绪，状态点 + 一句话说明。
- 主操作：一个明确的「开始说话」按钮，录音时变成「结束并输入」；旁边有热键提示。
- 最近输入：最近 5 条，显示时间、文本预览、来源应用；点击进入历史详情。
- 今日统计：字数、约省时间；不要做复杂图表。
- 底部状态条：模型、纠错档位、注入方式、隐私状态，点击可跳到对应设置。

布局建议：上方状态条，中部主操作区，下方左右分栏（最近输入 / 今日统计）。主操作区要留出足够的呼吸感。

#### 6.3 历史

- 左侧列表 + 右侧详情，或上方列表 + 下方详情；两种都可以，选信息密度更高的一种。
- 列表字段：时间、文本预览、字数、来源应用、状态（成功/失败）。
- 详情：原始转写、润色结果、差异高亮、时长、模型、注入结果。
- 操作：复制、重新注入、删除；顶部有搜索、日期筛选、清空。
- 空状态要给出「去首页说一句」的引导，而不是只写「暂无记录」。
- 明确提示：默认不保存音频；开启后才可回放。

#### 6.4 词库

- 三个分区：热词、替换规则、学习到的规则。
- 表格或列表：原词、指定写法、命中次数、来源（手动/学习）、操作。
- 顶部：搜索、新增、导入、导出。
- 学习规则可「转为正式规则」或「清空」。
- 需要一行轻量说明：热词影响识别，替换规则只影响纠错结果。

#### 6.5 设置

- 左侧二级导航 + 右侧表单，不要把所有项塞进一个长表单。
- 分组：通用（热键、开机启动、主题、语言）、识别（模型、麦克风、语言、GPU）、纠错（开关、强度、服务、Key）、注入（方式、延迟、终端类名）、隐私（历史、学习、音频留存、清空）、关于（版本、更新、诊断、许可证）。
- 每个字段下方有一行「为什么需要它」。
- 危险操作二次确认。
- API Key 输入框默认掩码，旁边有「测试连接」。
- 保存按钮固定在右下角，保存后给出明确反馈。

#### 6.6 悬浮胶囊

- 保持 180×56 左右的迷你尺寸，深色胶囊，不抢焦点。
- 状态：录音中（波形 + 计时 + 取消）、转写中、润色中、注入中、提示、错误。
- 错误态最多两行：一句原因 + 一个动作（如「模型未下载 · 去下载」）。
- 不要显示大段技术错误。

#### 6.7 托盘菜单

- 状态标题、开始/停止、打开控制台、暂停热键、历史、设置、退出。
- 菜单要短，不超过 7 项。

### 7. 设计系统（必须交付）

请给出一套可落地的 token，而不是只给颜色：

- **颜色**：背景、面板、浮层、边框、主文本、次文本、禁用、强调、成功、警告、错误；深色/浅色各一套。
- **字体**：中文用 Microsoft YaHei UI；字号阶梯（11/12/13/14/16/20/24）；字重（常规/中等/半粗）；行高。
- **间距**：4/8/12/16/24/32 六档，8px 网格。
- **圆角**：4/8/12/16 四档，说明用在哪。
- **阴影**：只允许 1–2 级，避免彩色阴影。
- **图标**：单色线性，24px 网格，1.5px 描边，16px 下仍可辨识。
- **组件**：按钮（主/次/文字/危险）、输入框、下拉、复选、开关、标签、分段控件、列表行、表格、空状态、加载、Toast、对话框、工具提示。
- **状态**：hover / pressed / focus-visible / disabled / loading / error；键盘焦点环必须清晰。

### 8. 交互与可访问性

- 所有操作可键盘到达；Tab 顺序合理；Esc 关闭弹层。
- 正文对比度 ≥ 4.5:1；不要用浅灰字放在深灰底上。
- 录音中必须有非颜色提示（波形/文案），照顾色觉障碍。
- 尊重系统「减少动画」设置。
- 窗口关闭默认隐藏到托盘，退出走托盘菜单；这个行为要在设置里有说明。
- 首次使用时，麦克风权限与模型下载要在需要时解释，不要一次性弹五个授权。

### 9. 技术约束（设计时必须考虑）

- 目标实现：PySide6（Qt Widgets + QSS + QPainter）。
- 不要设计 Qt 难以实现的效果：实时毛玻璃、复杂模糊、Web 级粒子、超大动态插画。
- 阴影、圆角、透明度、简单渐变、QPainter 自绘波形都可以实现。
- 图标与插图请用 SVG 或可导出 PNG；不要依赖字体图标。
- 主窗口无边框，标题栏需要自定义，但要保留拖动、最小化、关闭、缩放行为。
- 高 DPI（100%/125%/150%）下不能错位；给出 1x 设计稿与缩放说明。

### 10. 输出格式

请按以下顺序输出：

1. **设计策略**：200 字以内，说明你如何解决「像设置页」的问题。
2. **Design tokens**：颜色、字体、间距、圆角、阴影，附 hex 与用法。
3. **页面清单与线框**：每个页面一张 1000×660 画板（或 HTML/CSS 静态页），标注区域与层级。
4. **高保真界面**：首页、历史、词库、设置、向导各至少 1 张；深色为主，浅色至少给首页与设置。
5. **状态稿**：空状态、加载、错误、录音中、模型未就绪。
6. **组件库**：按钮、输入、列表、表格、Toast、对话框。
7. **Redline**：关键间距、字号、颜色、尺寸。
8. **迁移说明**：哪些效果用 QSS，哪些需要 QPainter 自绘，哪些建议放弃。

如果只能产出一个文件，请输出一份自包含的 HTML/CSS 静态原型，按 1000×660 画板排列，所有页面可切换查看。

### 11. 验收标准

- 遮住 Logo，仍然能认出这是「一个安静的语音输入工具」，而不是通用后台。
- 首页 3 秒内能看出：现在能不能用、按哪个键、刚才说了什么。
- 四个主页面有一致的栅格和 token，但各有明确的视觉识别点。
- 深色与浅色不是简单反色，而是同一套层级的两个版本。
- 所有按钮、输入、列表在 hover/focus/disabled 下都有明确反馈。
- 设计稿中的每个颜色、字号、间距都能在 token 表里找到。
- 不出现当前 UI 的「卡片套卡片 + 灰字说明」既视感。

### 12. 禁止事项

- 不要照抄 Wispr Flow、Superwhisper、VoiceInk、Linear、Notion 的界面。
- 不要用紫蓝渐变、霓虹、玻璃拟态、AI 光效、3D 吉祥物。
- 不要用「大标题 + 三张卡片 + 一堆图标」的 SaaS 落地页结构。
- 不要为了好看牺牲信息密度：这是工具，不是营销页。
- 不要引入新的功能概念；只重做现有页面与状态。
