## 3. 观察项（记录在案，暂不改代码）

| # | 方向 | 结论/理由 |
| --- | --- | --- |
| 观察A | `require_same_focus=False` 时，`paste_mode=auto` 的窗口类名取自录音结束时刻的窗口，与实际注入目标可能不一致 | 极端场景（用户主动关焦点校验 + 录音后切到终端）才会选错通道一次；fail-open 方向是回退通用 Ctrl+V，可接受 |
| 观察B | FallbackASR 粘滞态在 `_switch_lock` 内执行云端 transcribe | 串行化是有意为之（与 `_infer_lock` 的"推理串行"哲学一致），且切到云端后草稿预热默认已关闭，无并发热点 |
| 观察C | Unicode 直注对 `\n`/控制字符的处理依赖目标应用 | docstring 已声明限制；剪贴板通道仍是默认通道，终端场景 Unicode 是"可用"优先于"完美" |
| 观察D | 打包版仅验证了 DLL 随包与进程存活，**GPU 实际加载未验证** | 无头环境无法确认 CUDA 上下文；建议分发前在本机跑一次打包版，看控制台是否打印 CPU 回退日志 |
| 观察E | 设置窗口未给 `paste_mode` / `cloud_fallback` / `warmup_drafts` 提供控件 | 三个都是低频配置，已写入部署文档 §5.4 配置表；避免设置页继续膨胀，后续有真实需求再加 |
| 观察F | doctor 未校验新配置键值域（如 `paste_mode` 拼错、`warmup_drafts` 非数字） | 运行时已有 clamp/回退兜底（B2 模式），doctor 层校验属锦上添花 |

## 4. 已排除的怀疑方向（查证无问题）

| 方向 | 结论 |
| --- | --- |
| `make_asr` 同时构造本地+云端引擎的启动开销 | 无风险：两个构造函数均为轻量（模型懒加载、云端不联网探测），warmup 只预热主引擎 |
| 学习规则注入提示词的二次格式化风险 | 排除：refiner 用单趟链式 `replace` 占位符，规则内容中即使含 `{words_block}` 字面量也不会被再次解析；学习块处于词库数据定界声明之内，受同一防注入约束 |
| `learned_rules.json` 与 `history.json` 并发写 | 排除：两者各有独立锁 + 原子写（tmp + fsync + os.replace），且都只在 `_process` worker 线程单点调用 |
| 打包后 `config.example.json` / 测试文件混入 dist | 排除：PyInstaller 只收 import 图 reachable 的模块；dist 实测仅 `_internal` + exe + 使用说明 |
| `package.yml` 的 PowerShell 相对路径 | `Start-Process`/`Compress-Archive` 相对路径基于仓库根（actions/checkout 后的默认 cwd），语义正确 |
| 单字符热键 + auto 注入通道的组合 | 排除：热键选择在 settings 白名单内，与注入通道无耦合 |
