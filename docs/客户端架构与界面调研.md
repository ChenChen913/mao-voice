# 语音输入客户端调研：架构、形态与界面

> 面向 mao-voice 的下一步：从「一个跑在终端里的工具」变成「用户能双击打开、看得懂、愿意每天用的客户端」。
> 调研日期：2026-11-01。样本范围：Wispr Flow、Superwhisper、VoiceInk、Handy、OpenWhispr、CapsWriter-Offline、LazyTyper、闪电说、智谱 AI 输入法（小凹）。
> 文中的外部事实均附来源编号，见文末「参考来源」。

> **调研边界**：开源项目以 README/架构文档为准；闭源产品只依据公开文档与产品行为描述，不推断其内部实现。体积、内存等数字来自第三方对比或官方文档，属于量级参考，尚未在本项目实测。本文是设计调研与方案建议，尚未落地为代码。

## 0. 结论先行

1. **客户端形态**：主流做法是「托盘常驻 + 悬浮胶囊 + 一个可打开的控制台窗口」。录音入口永远是热键和胶囊，主窗口负责状态、历史、词典、设置，不承担日常录音操作。
2. **架构选择**：以 mao-voice 当前的技术栈（Python 引擎 + Windows 注入 + PyInstaller）为约束，第一版客户端建议用 **PySide6（Qt for Python）单进程**，先把 UI 与引擎的边界划清；如果之后要做跨平台或品牌级界面，再把 UI 换成 **Tauri 2 + Python sidecar**，引擎不动。
3. **不建议**：直接把现有 Tk 设置窗口放大成「客户端」，视觉天花板低；也不建议第一版就上 Electron（体积和内存代价大，且要引入 Node 技术栈）。
4. **界面基调**：深色优先、单一强调色（沿用现有的 #4A90D9）、12/16 两级圆角、以「状态 + 最近输入」为核心，不做卡片堆叠的仪表盘。
5. **功能优先级**：首次启动向导、首页状态、历史、词库、完整设置是 MVP；按应用切换「模式」、统计、更新检查是 P1；云端引擎切换、团队词典、插件是 P2。

### 1.2 从样本里得到的四条规律

1. **主窗口不是录音入口**。所有产品都把录音放在热键、悬浮条或菜单栏上；主窗口用来「看状态、管数据、调设置」。
2. **两个窗口几乎是标配**：一个极简浮层（录音/识别状态），一个完整控制台（历史/词典/设置）。OpenWhispr 直接把这条写进了架构文档 [7]。
3. **个性化是差异化的主战场**：词典、替换规则、按应用切换模式、风格预设。单纯「语音转文字」已经不够。
4. **本地/云端混合是常态**：Handy、VoiceInk、Superwhisper、LazyTyper 都允许用户选本地或云端模型；纯本地是卖点，不是限制。

## 2. 客户端应该是什么形态

### 2.1 三种范式

| 范式 | 代表 | 优点 | 缺点 | 是否适合 mao-voice |
| --- | --- | --- | --- | --- |
| 托盘/菜单栏常驻 + 悬浮条 | Wispr Flow、Handy、Superwhisper | 不打断当前工作；热键即用；符合语音输入的「随手」场景 | 用户不知道去哪看历史/设置，需要引导 | **是，作为主形态** |
| 可打开的控制台窗口 | OpenWhispr、小凹、VoiceInk | 承载历史、词典、模式、统计；可展示品牌 | 容易做成「设置页合集」，缺少产品感 | **是，但要做成仪表盘而不是设置页** |
| 输入法/键盘层 | 讯飞、搜狗、系统输入法 | 覆盖所有输入框；生态成熟 | 需要输入法框架、系统权限、审核；与现有注入方案不同赛道 | 否，暂不考虑 |

### 2.2 建议的最终形态

> **一个托盘图标 + 一个悬浮胶囊 + 一个控制台窗口**，三者共享同一份状态。

- **托盘**：常驻，显示「空闲 / 录音中 / 处理中」；右键菜单提供开始/停止、打开控制台、暂停热键、历史、设置、退出。
- **悬浮胶囊**：沿用现有 180×56 胶囊（图已在 README），增加「取消」与「录音时长」两个小能力；不抢焦点。
- **控制台**：用户主动打开（托盘、桌面快捷方式、F8），关闭时最小化到托盘而不是退出。

## 3. 架构选型

### 3.1 现有约束

| 约束 | 说明 |
| --- | --- |
| 引擎是 Python | faster-whisper / ctranslate2 / sounddevice / ctypes 注入，短期不可能重写 |
| 模型体积大 | medium 约 1.5GB，small 约 464MB；不能打进安装包 |
| Windows 深度集成 | 全局热键、前台窗口句柄、UIPI、剪贴板格式、终端类名 |
| 单人 + AI 辅助开发 | 每多一门语言/工具链，维护成本翻倍 |
| 已有打包链路 | PyInstaller onedir + GitHub Actions，CPU 版发布包已跑通 |

### 3.2 候选方案对比

| 方案 | UI 观感 | 附加体积 | 运行内存 | 开发复杂度 | 跨平台 | 复用现有 Python 引擎 | 主要风险 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| **PySide6（Qt Widgets / QML）** | 中上，可做出现代感 | 约 60–120MB | 中（Qt + Python） | 中 | 是（Win/mac/Linux） | 高，单进程直接调用 | Qt 样式与高 DPI 细节；LGPL 合规 |
| **Tauri 2 + Python sidecar** | 高，Web 前端随便做 | 壳 10–40MB，加上引擎后总量相近 | 中高（WebView2 + Python） | 高（Rust + Node + Python） | 是 | 高，引擎作为 sidecar 不动 | 三套工具链；sidecar 生命周期与 IPC；构建链复杂 |
| **Electron + React + Python sidecar** | 高 | 150–300MB | 高 | 中高（Node + Python） | 是 | 高 | 体积与内存；安全配置；两套运行时 |
| **pywebview + 本地 Web 服务** | 高 | 小（用系统 WebView） | 中 | 中低 | 是 | 高 | 像网页；本地端口安全；原生能力弱 |
| **WinUI 3 / WPF + Python 引擎** | 最高（原生 Windows） | 中 | 中 | 高（C# + XAML + 互操作） | 否 | 中 | 第三条语言栈；仅 Windows |

> 体积/内存数字来自第三方跨框架对比（Electron 约 150–300MB、Tauri 约 10–40MB）[14]，为量级参考，不是本项目实测值。

### 3.3 推荐路线

#### 第一版：PySide6 单进程客户端

理由：

1. **风险最低**：现有 16 个 Python 模块全部复用，录音、ASR、纠错、注入、历史的逻辑不需要搬语言。
2. **打包简单**：PyInstaller 对 PySide6 有成熟 hook；继续沿用当前 onedir + CPU/GPU 两档构建。
3. **体验够用**：Qt 可以做无边框窗口、圆角、阴影、动画、托盘、HiDPI；配合 QSS 可以做出与胶囊一致的暗色风格。
4. **为后续留门**：把「引擎」与「界面」按事件/命令边界拆开（见 3.4），未来换 Tauri 时只换 UI 壳。

需要注意：

- 不要 Tk 与 Qt 混在同一进程；建议一次性把悬浮胶囊、设置窗口、托盘都迁到 Qt。
- PySide6 是 LGPLv3，动态链接分发没问题，但要在安装包里附许可证文本并保留替换 Qt 库的可能（onedir 形态天然满足）。
- 只收集用到的 Qt 模块（QtCore/QtGui/QtWidgets，必要时 QtNetwork），避免把 WebEngine 等大件打进包。

#### 第二版（可选）：Tauri 2 + Python sidecar

触发条件（满足任意两条再考虑）：

- 明确要做 macOS / Linux；
- 要把客户端当作品牌门面，需要 Web 级的动效与排版；
- 愿意维护 Rust + Node + Python 三套工具链。

Tauri 官方支持把 PyInstaller 打包的 Python 程序作为 sidecar 嵌入 [15]，因此现有引擎可以原样保留，只把 UI 换成 React/Vue。

### 3.4 进程模型与通信

**第一版（单进程）**：

```text
┌───────────────────────────── 一个 Python 进程 ─────────────────────────────┐
│  UI 层 (PySide6)                Engine 层 (现有模块)                        │
│  主窗口 / 设置 / 历史 / 词典     热键 / 录音 / VAD / ASR / 纠错 / 注入        │
│         │  Qt Signal（事件）  ▲                │                            │
│         └────────────────────┘                │                            │
│                    Command（方法调用 / 队列）  ▼                            │
│                      配置 / 历史 / 日志（共享存储）                          │
└────────────────────────────────────────────────────────────────────────────┘
```

**第二版（引擎守护进程）**：

```text
┌────────────── UI 进程（PySide6 或 Tauri） ──────────────┐
│  主窗口 / 设置 / 托盘 / 悬浮胶囊                          │
│        ▲ events: state / level / transcript / error      │
│        │ commands: start / stop / cancel / config / test │
└────────┼─────────────────────────────────────────────────┘
         │ 本机 IPC（QLocalSocket 或 127.0.0.1 WebSocket，JSON 行协议）
┌────────┴──────────── Engine 进程（Python） ─────────────┐
│  热键 / 录音 / ASR / 纠错 / 注入 / 历史 / 模型下载 / 日志  │
│  单实例锁；UI 关闭不退出；崩溃由 UI 重启                   │
└───────────────────────────────────────────────────────────┘
```

通信协议建议：

| 项 | 建议 |
| --- | --- |
| 传输 | 单机用 QLocalSocket（Windows 命名管道）；Tauri 用 127.0.0.1 随机端口 WebSocket |
| 格式 | 一行一个 JSON：`{"id":1,"cmd":"start_recording"}` / `{"event":"state","data":{"state":"RECORDING"}}` |
| 鉴权 | 本机回环 + 启动时写入临时 token；拒绝非 127.0.0.1 连接 |
| 生命周期 | UI 启动时拉起引擎；引擎退出时 UI 提示并可重启；托盘退出才真正结束 |
| 单实例 | 命名互斥量；第二次启动唤起已有窗口 |
| 配置 | 版本化 JSON（`schema_version`），引擎为唯一写入者，UI 通过命令修改 |

不建议第一版就上 HTTP REST：对一个本机桌面工具来说，HTTP 的端口管理、跨域、鉴权都是额外负担；等换 Tauri 时再引入。

## 4. 客户端应该长什么样

### 4.1 五条设计原则

1. **常驻但不打扰**：启动后只在托盘；没有弹窗广告、没有每次启动的引导。
2. **状态永远可见**：录音中、转写中、注入中、出错，四个状态必须有明确反馈；错误要给「下一步」而不只是红色文字。
3. **一次只做一件事**：首页只回答三个问题：现在能不能用、刚才说了什么、我今天用了多少。
4. **可信可解释**：明确写出「音频不出本机，文本在开启纠错时发往你配置的端点」；每个权限在用到它的那一刻才申请。
5. **渐进披露**：新手只看到 5 个设置项；高级项收进「高级」折叠区，不把 40 个配置一次摊开。

### 4.2 信息架构

```text
mao-voice
├── 首次启动向导（仅一次）
│   ├── 1 欢迎与隐私边界
│   ├── 2 麦克风检测与试录
│   ├── 3 选择并下载模型
│   ├── 4 热键与交互方式
│   └── 5 纠错与隐私（API Key 可选）
├── 首页（仪表盘）
├── 历史
├── 词库
├── 模式（按应用）
└── 设置
    ├── 通用（热键 / 开机自启 / 主题 / 语言）
    ├── 识别（模型 / 设备 / 语言 / GPU）
    ├── 纠错（开关 / 强度 / 服务 / Key）
    ├── 注入（方式 / 延迟 / 终端类名）
    ├── 隐私（历史 / 学习 / 音频留存 / 清空）
    └── 关于（版本 / 更新 / 诊断 / 许可证）
```

### 4.3 界面线框

#### 4.3.1 首次启动向导

```text
┌────────────────────────────────────────────────────────────┐
│  ● ● ○ ○ ○                                    第 3 步 / 5  │
│                                                            │
│  选择识别模型                                               │
│  模型在本地运行，音频不会上传。                              │
│                                                            │
│  ┌──────────────────────────────────────────────────────┐  │
│  │ ○ Small   464 MB   快，适合日常短句                   │  │
│  │ ● Medium  1.5 GB   更准，推荐；首次需下载             │  │
│  └──────────────────────────────────────────────────────┘  │
│                                                            │
│  下载进度  ████████████░░░░░░  68%   约 3 分钟             │
│                                                            │
│                              [ 上一步 ]   [ 下一步 ]       │
└────────────────────────────────────────────────────────────┘
```

要点：

- 麦克风权限与试录放在第 2 步，让用户先「说一句」再看到成功；
- 模型下载显示体积、进度、可暂停/继续，并说明「不打包进安装包」；
- API Key 放在最后一步且可跳过，明确写「不填也能用，输出原始转写」；
- 不做强制登录、不做强制付费。

要点：

- 主按钮同时承担「开始」和「状态展示」，录音时变成波形与计时；
- 右下角「最近输入」是回流入口，点击进历史详情；
- 底部一行是当前配置的「状态胶囊」，点击对应项直接跳到设置；
- 不做大转盘、不做花哨图表，首页越安静越好。

```text
│  配森        Python        12     手动      编辑 / 删除              │
│  吉特哈布    GitHub         7     学习      编辑 / 删除              │
│  喵酱        （热词）        3     手动      编辑 / 删除              │
├──────────────────────────────────────────────────────────────────────┤
│  提示：热词会拼入识别提示词；替换规则只作用于纠错结果。               │
└──────────────────────────────────────────────────────────────────────┘
```

要点：

- 把「热词」与「替换规则」分开，避免用户困惑；
- 学习规则要显示命中次数与来源，可一键转正/清空；
- 导入导出用纯文本，保持与现有 `词库.txt` 兼容。

### 4.4 关键流程

**第一次使用**

1. 双击启动 → 欢迎页说明「本地识别、文本可选上行」；
2. 申请麦克风 → 试说一句 → 看到自己的波形与一句测试文本；
3. 选模型 → 下载（可暂停）→ 完成后自动加载；
4. 选热键 → 现场按一次验证；
5. API Key 可跳过 → 完成页提供「现在说一句」与「打开控制台」。

**日常使用**

1. 开机静默启动到托盘，模型后台预热；
2. 用户按热键 → 胶囊出现 → 说话 → 再按一次；
3. 状态依次「转写 → 纠错 → 注入」，成功后胶囊消失；
4. 文本进入历史（若开启），首页统计更新。

**失败恢复**

| 场景 | 客户端表现 |
| --- | --- |
| 模型未下载 | 胶囊与首页同时提示「模型未就绪」，提供「去下载」按钮 |
| 麦克风被占用 | 提示「麦克风被其他程序占用」并列出设备选择 |
| 注入被 UIPI 拦截 | 提示「目标窗口以管理员运行」+「文本已复制，可手动粘贴」 |
| 润色服务失败 | 提示「纠错失败，已输出原始转写」，不阻断注入 |
| 程序崩溃 | 下次启动展示上次异常日志摘要，提供「导出诊断」 |

### 4.5 视觉规范

| 项 | 建议 |
| --- | --- |
| 主题 | 深色默认，跟随系统；浅色作为可选项 |
| 背景 | 深色 `#121417`，面板 `#1B1E23`，边框 `#2A2F36` |
| 文本 | 主 `#E8EAED`，次 `#9AA0A6`，禁用 `#5F6368` |
| 强调色 | 沿用现有 `#4A90D9`；成功 `#27AE60`，警告 `#F39C12`，错误 `#E74C3C` |
| 字体 | 中文 `Microsoft YaHei UI`；数字用等宽（Consolas）；字号 12–14px，标题 18–20px |
| 圆角 | 卡片 12px，胶囊 16px，按钮 8px |
| 间距 | 8 / 12 / 16 / 24 四档；页面边距 24 |
| 动效 | 150–200ms ease-out；波形 30fps；尊重系统「减少动画」设置 |
| 图标 | 单色线性图标，24px 网格，1.5px 描边 |
| 可访问性 | 正文对比度 ≥ 4.5:1；所有操作可键盘到达；焦点环可见 |

### 4.6 文案基调

- 用「说一句」而不是「开始语音识别任务」；
- 用「模型未下载」而不是「ASR 初始化失败」；
- 错误文案统一结构：**发生了什么 + 你可以做什么**；
- 隐私文案只说事实：音频不出本机；开启纠错时文本会发往你配置的端点；历史默认关闭。

## 6. 对现有代码的改造清单

| 目标 | 改动 |
| --- | --- |
| UI 与引擎解耦 | 新增 `mao_voice/engine/service.py`，把 `main.App` 的状态机与管线封装成 `start/stop/cancel/status` 命令；UI 只订阅事件 |
| Qt 迁移 | `ui.py`（胶囊）改为 `ui/overlay.py`（Qt 无边框窗口，保留 WS_EX_NOACTIVATE 与置顶）；`settings_ui.py` 拆成 `ui/settings/*` |
| 主窗口 | 新增 `ui/main_window.py` 与 `ui/pages/{home,history,dictionary,modes,settings,about}.py` |
| 托盘 | 用 `QSystemTrayIcon` 替代 `pystray`（减少一个依赖，菜单与状态统一） |
| 配置 | `config.json` 增加 `schema_version` 与 `ui` 段（窗口位置、主题、上次页面） |
| 事件 | 现有 `_ui_queue` 改为 `EventBus`（Qt Signal 或简单回调），保留跨线程安全 |
| 测试 | 新增 `tests/test_client_ui.py`（pytest-qt 冒烟：窗口创建、页面切换、配置写入）；引擎单测保持 |
| 打包 | PyInstaller 增加 Qt 依赖收集；继续 CPU/GPU 两档；安装包内附 PySide6 LGPL 许可证 |

> 迁移顺序建议：**不要在同一进程里 Tk 与 Qt 混跑**。若想分批交付，可先让客户端以独立进程运行（PySide6 控制台 + 现有 Tk 引擎进程，走 3.4 的 IPC），验证主窗口后再合并为单进程；若走单进程路线，则一次性替换胶囊、设置窗口与托盘。每一步都应可运行、可回滚。

## 8. 风险与待验证

| 风险 | 说明 | 应对 |
| --- | --- | --- |
| Qt 无边框窗口行为 | 置顶、不抢焦点、点击穿透在 Qt 下与 Tk 行为不同 | 先用最小 Demo 验证 WS_EX_NOACTIVATE 与焦点行为，再迁移胶囊 |
| 打包体积 | Qt 模块收集过多会让包体再涨 60–120MB | 只收集 QtCore/QtGui/QtWidgets/QtNetwork；构建后检查 `_internal` |
| LGPL 合规 | PySide6 为 LGPLv3 | onedir 动态链接；附许可证；不修改 Qt 源码 |
| IPC 安全（第二版） | 本地 WebSocket 可能被其他本机程序连接 | 回环绑定 + 随机 token + 单实例锁 |
| 功能蔓延 | 「客户端」容易变成设置页合集 | 首页只保留状态/最近/统计三块；其他进二级页面 |
| 迁移回归 | 注入、热键、录音都是易碎链路 | 每阶段跑完整 pytest + `e2e_live.py --no-asr` |
