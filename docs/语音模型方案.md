# 语音模型方案调研

> 日期：2026-11-01。目标：解释「为什么之前能识别、现在不能」，评估本机已有模型能否直接使用，并给出 mao-voice 后续的模型管理方案。

## 1. 为什么之前能识别、现在不能

不是代码退步，是模型文件不在了。

- 项目 2026-09-28 的记录里，开发机 `voice_ime/models/` 下有 `faster-whisper-medium`，约 1.5GB；当时的测试、doctor、演示都基于它。
- `models/` 在 `.gitignore` 里，既不会进 Git，也不会进 Release 安装包（体积太大）。
- 当前这份工作区没有 `models/`，配置仍指向 `models/faster-whisper-medium`，所以按热键时会走到「模型不存在」。
- 之前那一长串 `Invalid model size ...` 是因为 faster-whisper 把本地路径当成了模型名。现在已改为可读提示：模型缺失时按热键直接提示去下载，ASR 层也会提前抛「模型未下载」。

结论：模型属于「用户本机资产」，不是仓库资产。换机器、重装、清理目录后都需要重新指定模型路径。

## 2. 本机已有模型盘点

本机已有的两个模型目录，格式都是 **faster-whisper / CTranslate2**，可以直接用：

| 模型 | 体积 | 目录内关键文件 | 兼容性 |
| --- | --- | --- | --- |
| `faster-whisper-large-v3` | 2.88 GB | `model.bin`、`config.json`、`tokenizer.json`、`vocabulary.json` | 可直接加载 |
| `faster-whisper-large-v3-turbo` | 1.51 GB | 同上 | 可直接加载 |

判断一个目录是不是 faster-whisper 模型，只看两点：

1. 目录里有 `model.bin`；
2. 同目录有 `config.json`、`tokenizer.json`、`vocabulary.json`。

实测：把配置指向 `large-v3-turbo` 后，完整链路「TTS 合成语音 → 本地转写 → 注入 → 剪贴板恢复」通过，识别结果为 `Hello, this is a Mao voice end-to-end test`，说明模型、GPU 加载、注入链路都正常。

## 3. 模型格式兼容性

| 格式 | 典型来源 | 能否被当前代码直接用 | 说明 |
| --- | --- | --- | --- |
| **CTranslate2 / faster-whisper** | `faster-whisper-*` 目录 | **可以** | 当前项目默认引擎，`model.bin` 是核心 |
| HuggingFace Transformers Whisper | `openai/whisper-large-v3` 原始权重 | 需要转换 | 用 `ct2-transformers-converter` 转成 CT2 目录 |
| whisper.cpp GGML / GGUF | `ggml-*.bin`、`gguf` | 不可以 | 需要另一个推理引擎（whisper.cpp / pywhispercpp） |
| FunASR / sherpa-onnx ONNX | Paraformer、SenseVoice | 不可以 | 需要 sherpa-onnx 或 FunASR 后端，不是 faster-whisper |

转换命令（供需要时使用）：

```bash
ct2-transformers-converter --model openai/whisper-large-v3 \
  --output_dir whisper-large-v3-ct2 \
  --copy_files tokenizer.json preprocessor_config.json \
  --quantization float16
```

## 4. 模型选型建议

| 模型 | 体积量级 | 中文 | 速度 | 适合 |
| --- | --- | --- | --- | --- |
| `large-v3` | 约 2.9 GB | 好 | 较慢 | 视频文稿、批量转录、追求准确率 |
| `large-v3-turbo` | 约 1.5 GB | 好 | 快很多 | **日常语音输入首选**；RTX 4060 可流畅跑 |
| `medium` | 约 1.5 GB | 较好 | 中 | 显存小、CPU 或老机器 |
| `small` | 约 464 MB | 一般 | 快 | 低配机器、首次下载体验 |
| `SenseVoice-Small` | 约 240 MB | 很好 | 很快 | 中文/粤语/日韩英，适合低延迟听写 |
| `Parakeet` | 约 478 MB | 英文强 | 快 | 英文听写，NVIDIA 优化 |

对本机的建议：

- **日常语音输入**：`large-v3-turbo`。已验证可用，速度与准确率平衡最好。
- **视频文稿批量转录**：`large-v3`。准确率更高，慢一点可以接受。
- **不建议同时常驻两个 large 模型**：8GB 显存会被挤爆；按任务切换即可。

## 5. 同类软件是怎么用模型的

调研了 8 个产品，归纳出 6 条通用做法：

### 5.1 模型按需下载，不在安装包里塞大模型

VoiceInk 把本地模型放在 `AI Models → Local`，用户可以下载、在 Modes 里选择、在模型卡片里删除或「在 Finder 中显示」[1]。Handy 也是安装后按需下载 Whisper / Parakeet 模型 [6]。这与本项目「模型不入库、不进包」的策略一致。

### 5.2 按硬件推荐模型，而不是让用户自己猜

VoiceWave 的安装向导会根据硬件推荐 Small 或 Large Turbo，并支持下载、校验、切换、重启后继续 [7]。Yap 在 Windows 上提供 13 个引擎，模型在应用内按需下载，空闲时从显存卸载 [4]。这类产品都把「模型选择」当成一个带状态的功能，而不是一个路径输入框。

### 5.3 多引擎注册表

WhisperKey 提供 13 个模型，从 31MB 到 1.6GB，并明确标注每个模型的用途 [3]。LazyTyper 提供 12 个模型，其中 5 个本地 [9]。CapsWriter-Offline 支持 Paraformer、SenseVoice、Fun-ASR-Nano、Qwen3-ASR 四种引擎 [8]。趋势是：**一个应用，多个推理后端，模型是可替换资产**。

### 5.4 本地优先，云端可选

Superwhisper 的 Modes 把「模型 + 提示词 + 输出格式」打包，用户可以在本地模型和云端模式之间切换 [5]。Handy 完全离线，但仍支持多种本地模型 [6]。本地模型负责隐私和离线，云端负责极致准确率，两者不冲突。

### 5.5 中文场景会单独优化

SpeakType 直接把 SenseVoice Small（约 240MB）作为默认，标注中文、粤语、日韩英，单句推理约 0.27 秒 [2]。VoiceInk 也支持 SenseVoice [1]。对中文听写来说，SenseVoice 这类模型在低延迟和标点方面有优势，Whisper large 系列更通用。

### 5.6 量化与设备选择是标配

faster-whisper 用 CTranslate2：GPU 常用 `float16`，CPU 常用 `int8`；也可以 `int8_float16` 在 GPU 上省显存 [10][11]。这解释了为什么同一份 `model.bin` 在不同机器上表现不同。

## 6. 对 mao-voice 的模型方案

### P0：先把「用本机已有模型」做顺

- 设置页的 `asr.model` 支持任意 faster-whisper 模型目录，并加一个「浏览目录」按钮。
- 选定目录后校验四件套：`model.bin`、`config.json`、`tokenizer.json`、`vocabulary.json`；不合法时给出人话提示。
- 显示模型体积、设备（GPU/CPU）、上次加载状态。
- 增加「扫描本机模型」：在用户选择的根目录下扫描包含 `model.bin` 的子目录，列出候选。
- 启动时如果模型缺失，首页直接显示「模型未就绪」，而不是等用户按热键。

### P1：模型管理页

- 模型列表：名称、体积、语言、速度、显存占用、来源（本机/下载）。
- 下载：进度、暂停/继续、校验、失败重试；默认存到 `%LOCALAPPDATA%\mao-voice\models`。
- 删除、在资源管理器中打开。
- 按硬件推荐：有 NVIDIA 显存 ≥ 6GB 推荐 turbo；否则 small 或 SenseVoice。
- 按用途切换：日常听写 / 视频文稿 / 英文听写。

### P2：多引擎

- 保持 faster-whisper 为默认引擎。
- 增加 sherpa-onnx 后端，接入 SenseVoice / Paraformer，服务中文低延迟场景。
- 如果未来要做 macOS，再评估 whisper.cpp / Core ML。
- 不建议第一版同时支持所有格式；先让 faster-whisper + 自定义目录稳定。

### 存储与分发原则

- 模型永远不进 Git、不进安装包。
- 默认模型目录放用户数据目录，不放在仓库目录。
- 允许自定义路径（本机已有模型可以原地复用，不复制、不占双份磁盘）。
- 只保存路径与校验信息，不保存模型副本。

## 7. 当前已经做的对接

- 本机配置已指向已有的 `large-v3-turbo` CT2 模型目录，客户端首页恢复「就绪」。
- 完整链路实测通过：TTS → turbo 转写 → 注入 → 剪贴板恢复。
- 设置页可以直接改模型路径；保存后会重建 ASR 引擎并后台预热。
- 模型目录缺失、目录缺少 `model.bin` 都会给出可读错误。
